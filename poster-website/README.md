# Сайт-визитка

React 19 + Vite + TypeScript. Одна длинная страница с разделами, как старый
сайт на Tilda (постерпринт.рф): первый экран-слайдер, «О нас», услуги,
портфолио, требования к макетам, «Нам доверяют», контакты с картой. Меню —
якоря на разделы. React Router оставлен для страницы 404 и будущих отдельных
страниц. Оформление — то же, что у системы: тёмный «цех», зелёный спот,
Inter.

Фотографий пока нет: на их местах заглушки PHOTO HERE с подписью, какой
снимок нужен (`src/components/Photo.tsx`).

## Разработка

```bash
npm install
npm run dev          # http://localhost:5174
npm run check        # проверка типов
npm run build        # сборка в dist/ (в репозиторий не идёт)
```

Порт 5174, а не 5173: у интерфейса системы (`../poster-ocr/web`) уже 5173,
оба dev-сервера могут работать одновременно. Ссылка «Вход для сотрудников» в
разработке проксируется на локальную систему (`vite.config.ts`), поэтому
для неё нужен запущенный uvicorn на 8000.

## Как сайт попадает на сервер

`Dockerfile`: Node собирает `dist/`, итоговый образ — маленький Caddy, который
отдаёт эти файлы и на любой адрес без файла возвращает `index.html`
(`Caddyfile` рядом). Главный Caddy сервера (`../deploy/Caddyfile`) проксирует
на него основной домен; система (CRM) живёт на своём поддомене (`crm.домен`)
и с сайтом не пересекается. Обновить сайт на сервере:

```bash
cd /opt/poster && git pull && docker compose up -d --build site
```

Сайт — отдельный контейнер: его сборка и перезапуск систему не трогают.
Первый запуск сервера — `../deploy/setup.sh`; сайт без CRM — режим `site`,
локально — `../poster.sh run site` (всё это — `../deploy/README.md`).

- **Кэш.** Файлы сборки (`/assets/…`, с хэшем в имени) кэшируются на год,
  всё остальное — `no-cache`: после обновления посетитель сразу получает
  новую страницу, а не старую со ссылками на удалённые файлы.
- **Ссылка «Вход для сотрудников»** ведёт на CRM: адрес приходит при сборке
  (`VITE_CRM_URL`, его docker-compose.yml собирает из `POSTER_CRM_DOMAIN`
  корневого `.env`). Без адреса ссылки на сайте нет; в разработке она ведёт
  на `/poster-crm/`, и vite проксирует её на локальную CRM.
- **Заголовки безопасности** (HSTS, `nosniff`, запрет встраивания на чужие
  сайты) сайту ставит главный Caddy (`../deploy/Caddyfile`). CSP нет
  намеренно: строгая политика сломала бы карту Яндекса во фрейме.

## Структура

    index.html              точка входа Vite, мета-теги, подключение шрифта
    public/fonts/           Inter — тот же набор, что у системы (без Google Fonts)
    src/content.ts          все тексты, услуги, контакты, адрес для карты
    src/App.tsx             порядок разделов, маршруты
    src/sections/           разделы страницы: шапка, слайдер, услуги, карта…
    src/components/         знак, заглушка фото, иконки, окно «Узнать стоимость»
    src/styles.css          стили; цвета — те же переменные, что в системе

## Что где менять

- **Тексты, услуги, телефон, почта** — `src/content.ts`.
- **Группы услуг** — `SERVICE_GROUPS` и поле `group` у каждой услуги в
  `src/content.ts`. На компьютере слева список по группам, справа выбранная
  услуга; на телефоне — раскрывающийся список.
- **Требования к макетам** — `FILE_FORMATS`, `BLEEDS`, `LAYOUT_RULES`,
  `FILE_RULES` в `src/content.ts`.
- **Карта** — `MAP` в `src/content.ts`. Сейчас метку ставит поиск Яндекса по
  адресу; если нужна точная точка — впишите `point` (долгота, широта).
  Виджет Яндекс.Карт во фрейме работает без ключа API.
- **«Узнать стоимость»** — открывает окно с WhatsApp (сообщение уже с
  названием услуги), Telegram, телефоном и почтой. Своей формы заявки нет:
  ей нужен сервер, который примет письмо.
- **Логотипы «Нам доверяют»** — `CLIENTS` в `src/content.ts`; лента едет сама
  и встаёт под курсором, скорость — `SECONDS_PER_LOGO` в
  `src/sections/Clients.tsx`.
